# Segurança

Não publique vulnerabilidades, chaves, dados de alunos ou provas de exploração em
issues ou pull requests públicos. Use a opção **Report a vulnerability** na aba
Security do GitHub, quando habilitada. Se ela estiver indisponível, contate o
responsável pelo repositório por um canal privado já conhecido.

Nunca envie credenciais reais ao repositório. Configure segredos somente nos
ambientes seguros do provedor de hospedagem e das integrações.

Caso uma credencial tenha sido publicada, revogue/substitua a credencial no
respectivo provedor. Apagar o arquivo ou tornar o repositório privado não invalida
cópias já obtidas. Planeje a rotação para preservar o serviço em produção.
